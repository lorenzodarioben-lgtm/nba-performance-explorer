## Run and inspect in Cloud or locally

Use Node22.12–22.x (package engines require <23), npm workspaces, and the committed lockfile. Run from repository root:

```sh
npm ci
npm run validate
npm run dev
```

Vite serves `http://localhost:5173`, forwarding `/api` to Express on3001. Default player mode outside production is **explicit fixture/demo mode**. The independent recorded datasets are genuine historical data even when the original player provider is in demo mode; preserve their separate source labels.

For genuine NBA player data, use `NBA_DATA_PROVIDER=nba-stats npm run dev` on Linux/macOS; in PowerShell set `$env:NBA_DATA_PROVIDER='nba-stats'` before `npm run dev`. No API key is required. Cloud egress to NBA/Wikimedia is unverified and can fail. Such failures must remain visible, not trigger fixture substitution. Inspect the recorded pages to design with genuine data independently of NBA connectivity.

For same-origin production-build preview, without deploying:

```sh
npm run build
NBA_DATA_PROVIDER=nba-stats NBA_ALLOW_FIXTURE_IN_PRODUCTION=false NODE_ENV=production FRONTEND_DIST=frontend/dist PORT=3002 node backend/dist/server.js
```

PowerShell: set those five environment variables individually, then run `node backend/dist/server.js`. Open `http://localhost:3002/explore`. Do not use Vite preview alone as proof of backend integration. Original catch-all intentionally renders the home page for unknown SPA paths; successful HTTP200 alone does not prove that a new route was registered.

Optional genuine acceptance, against an already running local genuine server only:

```sh
npm run smoke:engine
npm run smoke:closeout -- --write-report
```

The latter allows only localhost HTTP, at most100 sequential reads,30-second API/5-second SPA timeouts, a10-minute total budget and no retries. It validates public contracts, every registered SPA template, error statuses, genuine CSV content and exact built asset hashes. It is not ordinary CI and must not be repeatedly run against a failing source. `CLOSEOUT_ACCEPTANCE.json` records actual local results, not cloud/Render certification.

NBA player IDs are decimal strings. Team IDs use `nba:161061…`, game IDs use `nba:00223…` (recordedregular), `nba:00423…` (2024playoffs), `nba:00417…` (2018shots); research members `br:curryst01`, groups `study:GSW_2017_001`. These namespaces are not interchangeable. Internal2024game detail routes cannot accept a2018shot game ID; use `/games/shooting` or an explicitly safe source NBA link instead.

`null` means unavailable, not zero. Trade TOT rows count once. Shooting ratios use aggregated makes/attempts, not average percentages. TS uses the stated0.44 estimate. Qualification precedes ranking. Empirical midrank percentile is100*(strictly lower+0.5*tied)/N; population SD divides byN; competition ties share rank and skip following ranks. Opponent points/game is not defensive rating, final margin/game not net rating, time-normalized lineupPM not a possession rating. Similarity is a documented distance, not a prediction. See `CALCULATIONS.md` for full formulas and tested examples.

## Styling, accessibility and premium design opportunities

The expansion uses a white, scoped, intentionally plain research shell over the unchanged dark original app. It has no approved design tokens beyond existing original styles. Avoid global tag resets or token changes during exploratory work. Original assets/typography/screenshot DNA are in `frontend/public`, `styles.css` and `docs/assets/{home-desktop,home-mobile,player-profile-desktop,career-trends-desktop,player-comparison-desktop}.png`.

Potential design work: organize the long research navigation into a coherent information hierarchy; distinguish current provider queries from immutable archives through strong but restrained source/season labels; give metrics consistent units and precision; improve dense tables with purposeful column groups, pinned identity and responsive drill-down; clarify compared populations and sample sizes near charts; integrate games/teams/player links; make research bookmarks/filters easier to recognize. Original sports editorial tone, typography and imagery are useful reference material. The owner chooses the final art direction; these ideas do not authorize replacing assets or inventing content.

Phone layouts must retain essential source/sample/qualification/error information. Exact tables currently sit in focusable, labelled horizontal scroll groups. Preserve keyboard access and visible focus; prefer reflow and deliberate disclosure to clipping data. Full source credits may use accessible native disclosures, but must remain available in views and exports. Controls generally have44px minimum height. Do not hide unavailable cells, plot missing values at0, connect missing career/date gaps or make a tiny sample look definitive.

Charts need exact tables and meaningful legends; color alone cannot distinguish make/miss or compared series. Shot circles/crosses, career gaps and relative percentile scales carry real semantics. Keep original court origin/10units-per-foot/raw X/Y orientation, heaves and comparison axes. Maintain equal density shading across compared maps and separate all-filter summaries from paged marks. SVG metadata/export attribution must survive any replacement chart.

Motion should clarify focus, hierarchy and control feedback. Respect `prefers-reduced-motion`, interruption and keyboard behavior. No app-specific motion preference was delivered; it is deferred. Historical franchise mapping is also deferred: a permitted relocation candidate exists but was not integrated before expansion closed. Avoid decorative continuous motion, autoplay, heavy shader effects or extra chart libraries until an approved design need justifies them. Do not put statistical computation into animation code.

Source-error/loading/unsupported/empty/corrupt-storage states are real product states, not rare mockups. Design all of them. Preserve independently failing comparison slots, invalid-filter recovery and controls visible during errors. Keep duplicate-ID prevention, local storage caps, confirmation before clearing and recent-history consent intact.

## Validation, performance and operational limits

Final validation passed 737 tests (324 frontend, 413 backend across 88 files), format, lint, types and both builds. Genuine acceptance passed 87 bounded requests; all 36 route examples were rendered in phone QA. SVG exports reopen as valid XML after the namespace repair. Exact totals/evidence are authoritative in `HANDOFF.md`, `CLOSEOUT_ACCEPTANCE.json` and `VERIFICATION_LOG.md`.
